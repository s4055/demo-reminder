# 백엔드 리뷰 파이프라인

검토하고 분석하는 단계에서는 코드를 수정하지 않는다. 수정은 보고가 끝난 뒤 사용자가 요청할 때만 한다.

## 1. 검토

`backend-reviewer`를 Agent 도구로 실행한다. 검토 대상은 git 변경분이 아니라 현재 `backend/` 코드 전체이고, CLAUDE.md 관례와 정확성을 함께 검토한다. 사용자가 특정 패키지, 규칙, 관점만 짚었다면 그 범위를 프롬프트에 함께 넣는다.

## 2. 결과 분석

리뷰어의 보고가 도착하면, 보고 원문을 그대로 `review-analyst`에게 넘겨 실행한다.

리뷰어가 관례 위반과 정확성 문제 모두 `발견 사항 없음`으로 보고했다면 분석 단계는 건너뛴다.

## 3. 사용자 보고 (한국어)

- 검토 기준이 된 CLAUDE.md 경로와 규칙 수, 규칙별 준수·위반 현황
- 분석가의 확정·가능성 항목을 우선순위 순으로 정리하고, 각 항목에 관례/정확성 구분과 `파일:라인`을 붙인다
- 기각된 항목은 개수와 한 줄 이유만 적는다
- 마지막에 "수정을 진행할까요?"로 끝내고, 사용자가 동의하기 전에는 코드를 고치지 않는다
